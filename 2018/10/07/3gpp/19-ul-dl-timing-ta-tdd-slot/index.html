    1. 为什么需要上下行定时控制

    在蜂窝网络中，多个 UE（用户终端）分布在距基站（gNB）不同距离的位置，信号从 gNB 到 UE 存在不同的传播延迟。

    主要问题： 若各 UE 以相同的绝对时刻开始发送上行信号，距离远的 UE 信号到达 gNB 时，已比近端 UE 晚了若干微秒，导致上行子帧/时隙对齐破坏，不同 UE 的 PUSCH / PUCCH 在 gNB 侧互相重叠干扰。

    解决方案：Timing Advance（定时提前）

    让每个 UE 根据自身与 gNB 之间的往返传播时延（RTD），提前发送上行帧，使所有 UE 的上行信号都在同一时刻到达 gNB。这就是 TA 机制的基本原理。

    对于 TDD 系统，还存在额外的挑战：上下行使用同一频率资源，需要在时间维度上精确切换。切换时需要保留一段保护时间（Guard Period），以容纳：

    • UE 的 TA 补偿余量（避免远端 UE 的上行信号回传时，与 gNB 已开始的下行传输重叠）
    • 收发机从发送切换到接收（或反向）所需的硬件转换时间

    2. 5G NR 基本时间单元 Tc 与 Ts

    在深入 TA 公式之前，需要先了解 5G NR 的时间基准单元。

    Tc（NR 基本时间单元）

    $$T_c = \frac{1}{\Delta f_{max} \cdot N_f} = \frac{1}{480 \times 10^3 \times 4096} \approx 0.509 \text{ ns}$$

    其中：

    • $\Delta f_{max} = 480 \text{ kHz}$（最大子载波间距）
    • $N_f = 4096$（FFT 点数）

    Tc 是 5G NR 所有时间计算的最小粒度单位，定义于 TS 38.211 第 4.1 节。

    Ts（LTE / 遗留时间单元）

    $$T_s = \frac{1}{2048 \times 15000} = \frac{1}{30.72 \times 10^6} \approx 32.55 \text{ ns}$$

    LTE 使用 Ts 作为基本单元。NR 中：$T_s = 64 \cdot T_c$。

    在一些 NR 规范文本中，特别是 TA 公式推导，有时仍会引用 Ts 表示宏观时间量级，但精确计算以 Tc 为准。

    3. Timing Advance（TA）机制

    3.1 TA 的物理含义与公式

    根据 TS 38.211 第 4.3.1 节，UE 上行帧的发送时刻定义为：

    $$T_{TA} = \left(N_{TA} + N_{TA,offset}\right) \times T_c$$

    UE 需在接收到对应下行帧之前 $T_{TA}$ 时刻，开始发送上行帧 $i$，即：

    这样，尽管信号从 UE 到 gNB 存在传播延迟 $\tau_p$，gNB 收到的上行帧起点，仍与 gNB 自身的下行帧起点对齐。

    参数说明：

    参数 含义
    $N_{TA}$ 由 gNB 通过信令下发的定时提前量（整数，单位 Tc）
    $N_{TA,offset}$ 系统内置偏移量，因频段和双工方式而异
    $T_c$ NR 基本时间单元（≈ 0.509 ns）

    $N_{TA}$ 与 TA 命令值的关系（RAR 场景）：

    $$N_{TA} = TA \times 16 \times 64 / 2^\mu$$

    其中 $TA$ 是 RAR 中携带的 12-bit 定时提前命令值（0～3846），$\mu$ 是子载波间距参数（Numerology）。

    物理直觉： 若 UE 距 gNB 为 $d$ km，单程传播时延 $\tau_p = d/c$，则往返时延约为 $2\tau_p$，TA 的补偿量约等于 $2\tau_p$。例如，距离 1.5 km 时，$\tau_p \approx 5,\mu s$，需提前约 10 μs 发送。

    3.2 NTA,offset 说明

    $N_{TA,offset}$ 是在 TA 数值之外额外引入的固定偏移，主要用于为 TDD 收发机的硬件切换（DL→UL transceiver switching）留出时间裕量。

    根据 TS 38.133 Table 7.1.2-2 及 TS 38.213 第 4.2 节，$N_{TA,offset}$ 取值如下：

    频段 双工方式 NTA,offset（单位 Tc） 等效时间
    FR1（< 6 GHz） TDD（默认） 25600 ≈ 13.03 μs
    FR1（< 6 GHz） FDD 0 0
    FR1（< 6 GHz） TDD（LTE-NR 共存场景） 39936 ≈ 20.33 μs
    FR2（> 6 GHz，mmWave） TDD 13792 ≈ 7.02 μs
    • FDD 场景：UL/DL 使用不同频率，无需 UL→DL 转换裕量，故 offset = 0。
    • TDD FR1：默认 25600 Tc（约 13 μs），涵盖 ~10 μs 硬件切换 + 余量。
    • TDD FR2（mmWave）：硬件切换更快（约 5 μs），offset 更小。

    网络通过 ServingCellConfigCommon 或 ServingCellConfigCommonSIB 中的 n-TimingAdvanceOffset IE 将该值配置给 UE；若未配置，FR1 默认取 25600。

    3.3 初始 TA：随机接入响应（RAR）

    UE 在初次接入小区或重新同步时，通过随机接入流程获得初始 TA。

    流程概述（TS 38.213 / 38.321）：

    最大小区半径估算（FR1，30 kHz SCS，μ=1）：

    $$N_{TA,max} = 3846 \times 16 \times 64 / 2^1 = 3846 \times 512 = 1969152 \text{ Tc}$$

    $$T_{TA,max} = 1969152 \times T_c \approx 1969152 \times 0.509 \text{ ns} \approx 1002 \text{ μs}$$

    对应最大单程传播时延约 501 μs，换算距离约 150 km（理论值，实际受限于 PRACH 格式和 Guard Period）。

    注意：对于 μ=1（30 kHz SCS），实际 PRACH 格式通常支持约 15～100 km 的小区半径，取决于所选 PRACH 格式（Format 0、A1、A2、B4 等）的循环前缀长度。

    3.4 TA 维护：MAC CE 命令

    UE 连接态下，gNB 持续监测上行信号（PUSCH、SRS）的到达时刻偏差，在必要时通过 MAC CE（Timing Advance Command MAC CE） 下发调整命令。

    MAC CE 结构（TS 38.321 第 6.1.3.5 节）：

    • TAG ID：标识本次调整适用的 Timing Advance Group（见 3.6 节）
    • Timing Advance：6 bit，取值 0～63，代表相对调整量

    调整量计算：

    $$\Delta N_{TA} = (TA_{MAC-CE} - 31) \times 16 \times 64 / 2^\mu$$

    • $TA_{MAC-CE} = 31$：不调整（中间值）
    • $TA_{MAC-CE} > 31$：上行发送提前（UE 更远，或已跑出同步）
    • $TA_{MAC-CE} < 31$：上行发送推后

    每步调整粒度（μ=1，30 kHz SCS）：

    $$\Delta T = 16 \times 64 / 2 \times T_c = 512 \times 0.509 \text{ ns} \approx 260.6 \text{ ns}$$

    对应距离约 39 m（往返），即单程约 19.5 m。这是 gNB 能通过 TA 命令进行调整的最小粒度。

    3.5 TA 的调整时延与精度要求

    根据 TS 38.213 第 4.2 节，UE 在收到 TA 命令后，并非立即应用，而是有一定的调整窗口：

    若 UE 在上行时隙 $n$ 收到 TA 命令（MAC CE），对应 TA 调整从上行时隙 $n + k + 1$ 的开头起生效，其中 $k$ 的计算涉及 UE 处理能力和 PDSCH 处理时间（$N_1 + N_2$ 符号）。

    精度要求（TS 38.133）：

    UE 对 TA 命令的执行精度：

    • 相对于前一次上行发送时刻，调整误差不超过 $\pm 4 \cdot T_c$（约 ±2 ns）

    3.6 TAG（Timing Advance Group）

    在载波聚合（CA） 或双连接（DC） 场景下，一个 UE 可能同时维护多个服务小区，而不同小区可能具有不同的传播时延（例如主小区 PCell 和辅小区 SCell 位于不同物理位置的天线）。

    TAG 机制（TS 38.321）：

    • 每个 TAG 包含一组小区，组内所有小区共享同一个 TA 值
    • 包含 PCell 的 TAG 称为 pTAG（primary TAG），由 RAR 或 MAC CE 统一控制
    • 其余 TAG 称为 sTAG（secondary TAG），各自独立维护 TA

    同 TAG 规则：

    • 同一 TAG 内的上行小区，共享相同的 TA 值，上行发送时刻相同
    • 若 PCell 为 FDD、SCell 为 TDD，且属同一 TAG，UE 可假设二者传播时延相同

    3.7 TA 计时器（timeAlignmentTimer）

    为防止 UE 偏离时间对齐状态（例如 gNB 长时间未发送 TA 调整命令），3GPP 定义了 **timeAlignmentTimer**（TS 38.321）。

    • UE 每次收到 TA 命令时，重启该计时器
    • 若计时器超时，UE 认为该 TAG 的上行时间对齐已失效，停止上行发送，等待重新获得 TA（通常通过 RACH 流程）
    • 取值范围：500 ms、750 ms、1280 ms、1920 ms、2560 ms、5120 ms、10240 ms、infinity

    4. TDD 帧结构基础回顾

    4.1 Numerology 与时隙长度

    5G NR 支持多种 Numerology（子载波间距参数 μ），定义于 TS 38.211 Table 4.2-1 和 Table 4.3.2-1：

    μ 子载波间距 (SCS) 时隙长度 每子帧时隙数 每帧时隙数 适用场景
    0 15 kHz 1.0 ms 1 10 FR1 低频（LTE 兼容）
    1 30 kHz 0.5 ms 2 20 FR1 主流（n78 等）
    2 60 kHz 0.25 ms 4 40 FR1 / FR2
    3 120 kHz 0.125 ms 8 80 FR2（mmWave）
    4 240 kHz 0.0625 ms 16 160 FR2 参考信号

    帧结构固定规则（TS 38.211）：

    • 无线帧长度：固定 10 ms，System Frame Number（SFN）取值 0～1023
    • 子帧长度：固定 1 ms
    • 时隙包含：14 个 OFDM 符号（Normal CP）或 12 个符号（Extended CP，仅 μ=2）
    • 时隙长度 = $1,\text{ms} / 2^\mu$

    4.2 符号类型：D / U / X（Flexible）

    5G NR TDD 在符号级别定义上下行方向，比 LTE 的子帧级别配置更加灵活。

    根据 TS 38.211 第 4.3.2 节，每个 OFDM 符号可被标记为：

    符号类型 说明
    D（Downlink） 只用于下行传输（gNB→UE）
    U（Uplink） 只用于上行传输（UE→gNB）
    X（Flexible） 可灵活用于上行或下行，也可作为保护间隔

    UE 行为约束：

    • UE 只能在 D 或 X 符号上接收下行
    • UE 只能在 U 或 X 符号上发送上行
    • 非全双工 UE 在最后一个 DL 符号结束后，等待至少 $T_{Rx-Tx}$ 时间才能发送上行（UE 收发切换时间，FR1 约 20 μs，FR2 约 10 μs）

    5. TDD 时隙格式（Slot Format）

    5.1 时隙格式表（TS 38.213 Table 11.1.1-1）

    为规范化 TDD 配置，3GPP 在 TS 38.213 第 11.1.1 节中定义了 56 种时隙格式（Format 0 ～ Format 55），每种格式规定了一个时隙内 14 个符号的 D/U/X 分配方式。

    以下列出典型的几种（Normal CP，14符号/时隙）：

    格式编号 符号 0~13 说明
    Format 0 D D D D D D D D D D D D D D 全下行时隙
    Format 1 U U U U U U U U U U U U U U 全上行时隙
    Format 2 X X X X X X X X X X X X X X 全 Flexible 时隙
    Format 28 D D D D D D D D D D D D D X 末尾 1 个 Flexible
    Format 34 D D D D D D D D D D X X X X 末尾 4 个 Flexible
    Format 35 D D D D D D D D D X X X X X 末尾 5 个 Flexible
    Format 48 X X X X X X X X X X X X X U 首部 13 个 Flexible + 末尾 1 个 U
    Format 55 D D D D D D D D D D X U U U 典型 SSF：10D+1X+3U

    完整的 56 种格式详见 TS 38.213 Table 11.1.1-1。这些格式本身不是直接配置给 UE 的参数，而是通过 tdd-UL-DL-ConfigurationCommon + tdd-UL-DL-ConfigurationDedicated + DCI 动态信令组合推导出最终每个符号的 D/U/X 属性。

    5.2 特殊时隙（SSF / S-slot）

    在 LTE TDD 中，特殊子帧（Special Subframe，SSF） 是固定格式的，由 DwPTS（下行导频时隙）、GP（保护间隔）、UpPTS（上行导频时隙）三段组成，通过 SIB 中 specialSubframePatterns 参数配置（共 10 种格式）。

    5G NR 中 SSF 的演进：

    5G NR 取消了固定的 SSF 概念，改为灵活的特殊时隙（S-slot）。本质上，S-slot 就是一个包含 DL 符号 + Flexible 符号（Guard Period）+ UL 符号的混合时隙，可通过 tdd-UL-DL-ConfigurationCommon 参数自由配置其中各部分的符号数。

    典型 S-slot 结构（30 kHz SCS，Normal CP，14 符号）：

    这就是业界常说的 “10:2:2” 配置（10 个下行 + 2 个 GP + 2 个上行）。GP 符号标记为 Flexible（X）。

    S-slot 的灵活性：

    • DL 符号数：0～13
    • GP 符号数：0～13（标记为 X，实际用作 Guard Period 或保持为 Flexible）
    • UL 符号数：0～13
    • 约束：$n_{DL} + n_{GP} + n_{UL} = 14$

    根据 GSMA 5G TDD 同步指南建议，对于 DDDSU 配置（30 kHz SCS），S-slot 推荐配置为 10:2:2，在需要更大覆盖范围（更长 GP）时可调整为 10:4:0 等。

    5.3 Guard Period 的作用

    Guard Period（GP）是 TDD 系统中 DL→UL 切换时的 **”沉默时段”**，其大小需满足两个约束：

    约束 1：覆盖最大小区半径

    $$T_{GP} \geq 2 \times \tau_{p,max} + T_{switch}$$

    其中：

    • $\tau_{p,max}$：最大单程传播时延（对应小区覆盖半径）
    • $T_{switch}$：gNB 和 UE 的收发机切换时间总和（FR1 约 20 μs，FR2 约 10 μs）

    约束 2：TA 补偿余量

    TA 机制已预先补偿了大部分传播时延，但 GP 仍需容纳：

    • 远端 UE 上行信号的最大可能时延残余
    • gNB 从发送下行切换到接收上行的转换时间

    示例计算（30 kHz SCS，Symbol 长度 ≈ 35.7 μs）：

    GP 符号数 GP 时长 对应最大小区半径（扣除切换时间）
    1 符号 35.7 μs ≈ 7.1 km
    2 符号 71.4 μs ≈ 14.2 km
    3 符号 107.1 μs ≈ 21.4 km
    4 符号 142.8 μs ≈ 28.6 km

    注：以上为粗估值，实际需结合 $N_{TA,offset}$（已内置 ~13 μs 的切换余量）综合计算。大多数城区宏站配置 2 个 GP 符号即可满足要求。

    6. TDD UL/DL 配置信令机制

    5G NR 支持三层叠加的 TDD 时隙配置机制，灵活性远高于 LTE。根据 TS 38.213 第 11.1 节和 TS 38.331 的定义：

    优先级：DCI > Dedicated RRC > Common RRC（更高层可覆盖低层，但不能更改低层已固定为 D 或 U 的符号，只能更改 Flexible 符号）

    6.1 tdd-UL-DL-ConfigurationCommon（小区公共配置）

    通过 SIB1 广播给小区内所有 UE，定义小区范围内的 TDD 基础模式。

    RRC 消息结构（TS 38.331）：

    参数解读：

    • dl-UL-TransmissionPeriodicity：TDD 周期（一个 Pattern 的重复周期）
    • nrofDownlinkSlots：Pattern 中完整的下行时隙数
    • nrofDownlinkSymbols：特殊时隙（S-slot）内开头的 DL 符号数（0 表示无 S-slot 的 DL 部分）
    • nrofUplinkSlots：Pattern 中完整的上行时隙数
    • nrofUplinkSymbols：特殊时隙内末尾的 UL 符号数

    Pattern 内时隙排列规则：

    双 Pattern 时，总周期 = Period1 + Period2，且必须能整除 20 ms。

    配置示例（DDDSU，30 kHz SCS，5 ms 周期）：

    解读：周期 5 ms，共 10 个时隙（30 kHz SCS）：

    • 时隙 0～6：全 DL（7 个）
    • 时隙 7：S-slot（6 个 DL + 4 个 Flexible（GP） + 4 个 UL）
    • 时隙 8～9：全 UL（2 个）

    6.2 tdd-UL-DL-ConfigurationDedicated（UE 专属配置）

    通过 RRC Reconfiguration 消息下发给特定 UE，用于在 Common 配置的基础上，进一步将部分 Flexible（X）符号明确分配为 D 或 U。

    应用场景：

    • 为特定 UE 提供更多上行资源（将 Flexible 时隙改为 UL）
    • 为 URLLC 业务配置小时隙（Mini-Slot）优先的上行调度

    约束： 只能将 Common 配置中的 Flexible（X）符号改为 D 或 U；不能将已固定的 D 改为 U，或将已固定的 U 改为 D。

    6.3 DCI 动态指示：SFI（Slot Format Indicator）

    DCI Format 2_0（TS 38.213 第 11.1.1 节）在 PDCCH 上携带 SFI（Slot Format Indicator），可以在时隙级别动态告知 UE 接下来若干时隙的 D/U/X 分配，从而实现动态 TDD。

    工作原理：

    • 覆盖范围：DCI 2_0 可一次性更新多个时隙的格式
    • 适用场景：流量不对称变化较快（如视频直播切换为上传）的动态调整
    • 实际部署：目前大多数运营商仍以半静态配置（RRC）为主，动态 TDD 应用较少

    7.4 mmWave（FR2）帧结构特点

    FR2（mmWave，> 24.25 GHz）通常使用 μ=3（120 kHz SCS），时隙长度仅 0.125 ms，因此：

    • 单个符号长度 ≈ 8.9 μs（含 CP）
    • 传播距离短（室内/热点覆盖），TA 值较小
    • GP 通常配置 1～2 个符号即可（覆盖距离 < 1 km）
    • $N_{TA,offset} = 13792 \text{ Tc} \approx 7.02,\mu s$（内含较小的切换余量）

    8. TA 机制与 TDD Guard Period 的关系

    TA 和 GP 是 TDD 系统定时控制的两个互补机制，二者共同决定了系统能支持的最大小区半径：

    GP 需容纳的时间量：

    $$T_{GP} \geq 2\tau_{p,max} - N_{TA,offset} \times T_c + T_{switch}$$

    其中 $N_{TA,offset} \times T_c$（约 13 μs，FR1 TDD）是系统预置的偏移，已经占用了一部分 GP 的”名义空间”：

    • 若 UE TA 已完全补偿了传播时延，则 GP 主要用于收发切换时间
    • 若存在 TA 误差或 UE 刚接入尚未获得准确 TA，GP 可吸收部分时延残余

    结论： GP 的长度直接决定了 TDD 系统的最大小区覆盖半径，而 TA 机制则决定了已连接 UE 的上行时间对齐精度。两者缺一不可。

    10. 本文小结

    5G NR 上下行定时包含两项主要机制：

    Timing Advance（TA）：

    • TA 的基本公式为 $T_{TA} = (N_{TA} + N_{TA,offset}) \times T_c$，UE 据此在下行帧接收时刻之前提前发送上行帧
    • 初始 TA 在随机接入响应（RAR）中以 12-bit 值下发，维护 TA 通过 MAC CE（6-bit）相对调整
    • $N_{TA,offset}$ 为收发切换预留时间：FR1 TDD 默认 25600 Tc（≈13 μs），FR2 TDD 为 13792 Tc（≈7 μs），FDD 为 0
    • TAG 机制支持 CA/DC 场景下多服务小区的独立 TA 管理
    • timeAlignmentTimer 超时后 UE 停止上行发送，需重新 RACH 获取 TA

    TDD 时隙配置：

    • 5G NR 在符号级别定义 D/U/X，比 LTE 的子帧级别更灵活
    • 3GPP 定义了 56 种时隙格式（Format 0～55），实际配置通过三层叠加实现
    • tdd-UL-DL-ConfigurationCommon（SIB1）→ tdd-UL-DL-ConfigurationDedicated（专属 RRC）→ DCI Format 2_0（SFI）动态覆盖
    • 特殊时隙（S-slot）中的 Flexible 符号（Guard Period）是 TA 补偿与收发切换的时间缓冲
    • 常见部署模式：DDDSU（5 ms，适合 FR1 eMBB）、DDDDDDDSUU（10 ms，兼容 LTE）

    TA 机制与 Guard Period 共同保证了多用户上行同步与 TDD 双工安全切换，是理解 5G NR 物理层调度与覆盖规划的基础。
