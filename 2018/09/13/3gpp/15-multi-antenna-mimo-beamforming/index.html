    1. 多天线技术概述与演进

    多天线技术是 5G NR 实现高频谱效率、大容量、广覆盖的核心手段。与 LTE 相比，NR 将多天线能力推进到了全新维度。

    1.1 从 LTE 到 NR 的演进

    技术维度 LTE（R8~R13） 5G NR（R15+）
    最大天线端口数 8（R10 引入） 32（数字域），物理单元可达数百
    最大传输层数 8 层 8 层（DL），4 层（UL）
    波束管理 无系统化框架 P1/P2/P3 标准流程
    CSI 码本 Type I（LTE 式） Type I + Type II + eType II
    mmWave 支持 无 FR2（24.25 GHz～52.6 GHz）全面支持
    混合波束赋形 无 FR2 标准部署方式

    1.2 多天线技术的核心收益

    多天线技术提供三类基本增益：

    阵列增益（Array Gain）：多天线同相叠加，信噪比提升正比于天线数 $N$，即 $10\log_{10}(N)$ dB。64 元件阵列理论提供约 18 dB 增益，可补偿 mmWave 额外路径损耗。

    空间复用增益（Spatial Multiplexing）：在散射丰富的信道中，多流并发传输，峰值吞吐量与 $\min(N_T, N_R)$ 正相关（$N_T$ 为发送天线数，$N_R$ 为接收天线数）。

    分集增益（Diversity Gain）：多路径信号独立衰落，合并后可降低链路中断概率，改善覆盖边缘体验。

    2. 天线阵列与空间信道模型

    2.1 天线端口（Antenna Port）的抽象

    3GPP 在 TS 38.211 中定义了天线端口（Antenna Port）的概念：天线端口是逻辑实体，两个信号在同一天线端口上传输，意味着 UE 可以从一个信号推断同端口其他信号的信道特性（准同址假设）。

    物理天线元件（Physical Antenna Element）通过模拟移相网络映射到天线端口，端口数远少于物理元件数，这是混合波束赋形的核心思想。

    2.3 信道矩阵与奇异值分解

    空间信道可用矩阵 $\mathbf{H} \in \mathbb{C}^{N_R \times N_T}$ 表示，对其进行奇异值分解（SVD）：

    $$\mathbf{H} = \mathbf{U} \mathbf{\Sigma} \mathbf{V}^H$$

    • $\mathbf{U}$：接收端奇异向量（UE 侧最优接收波束）
    • $\mathbf{V}$：发送端奇异向量（gNB 侧最优预编码矩阵）
    • $\mathbf{\Sigma}$：奇异值对角矩阵（对应各层信道增益）

    非零奇异值的个数即为信道秩（Rank），决定最大可复用流数。实践中，UE 通过 CSI 反馈将近似的 $\mathbf{V}$ 以码本索引（PMI）的形式告知 gNB。

    3. SU-MIMO：单用户多天线

    SU-MIMO（Single-User MIMO）是将多天线增益集中服务单一 UE 的技术，目标是最大化单用户峰值吞吐量。

    3.1 传输层与空间复用

    在 5G NR 中，传输层（Transmission Layer）是空间复用的基本单位：

    • 下行（DL）：最多 8 层（TS 38.214 clause 5.4）
    • 上行（UL）：最多 4 层（TS 38.214 clause 6.4）

    数据流经过层映射（Layer Mapping）分配到各传输层，再经过预编码（Precoding）映射到天线端口：

    3.2 秩指示（RI）的选择

    UE 根据信道条件上报秩指示（RI，Rank Indicator），建议 gNB 使用的传输层数：

    • RI = 1：信道秩低，适合波束赋形增益优先（如小区边缘，信道单路径主导）
    • RI > 1：信道散射丰富，可同时传输多流（如室内、富散射环境）

    RI 与 PMI、CQI 共同组成 CSI 三元组（TS 38.214 clause 5.2.1）。

    3.3 下行 SU-MIMO 调度流程

    4. MU-MIMO：多用户多天线

    MU-MIMO（Multi-User MIMO）是在同一时频资源上向多个 UE 并发传输的技术，通过空间域的用户分离提升小区总吞吐量（小区级频谱效率）。

    4.1 MU-MIMO 的原理

    设小区内有 $K$ 个 UE，第 $k$ 个 UE 的信道为 $\mathbf{h}_k$，gNB 使用预编码向量 $\mathbf{w}_k$，则第 $k$ 个 UE 接收到的信号为：

    $$y_k = \mathbf{h}_k^H \mathbf{w}k s_k + \sum{j \neq k} \mathbf{h}_k^H \mathbf{w}_j s_j + n_k$$

    其中第二项为多用户干扰（MUI，Multi-User Interference）。MU-MIMO 预编码的目标是：在满足发送功率约束的前提下，使各 UE 的有用信号最大化，干扰最小化。

    理想情况下，若 $\mathbf{w}_j$ 位于 $\mathbf{h}_k$（$k \neq j$）的零空间，则用户间无干扰，即实现了零强迫（ZF，Zero-Forcing）预编码。

    4.2 SU-MIMO 与 MU-MIMO 对比

    维度 SU-MIMO MU-MIMO
    服务对象 单 UE 多流 多 UE 并发
    主要增益 单用户峰值速率 小区总吞吐量（频谱效率）
    对 CSI 精度要求 中等 高（需精准区分用户波束）
    用户间隔离 不需要 需要空间隔离
    适用码本 Type I Type II / eType II
    典型场景 高速移动、低散射 密集热点、多用户静止

    4.3 MU-MIMO 的配对条件

    gNB 的调度器在选择 MU-MIMO 配对 UE 时需满足：

    1. 空间正交性：被配对的 UE 信道方向尽量正交（夹角接近 90°）
    2. 信道互补性：各 UE 的 PMI 对应方向不重叠
    3. 功率平衡：各 UE 路径损耗差异不过大，避免远近效应

    实践中，gNB 基于 UE 上报的 Type II 码本（包含更精细的空间信息）进行配对决策。

    5. 波束赋形原理与实现架构

    5.1 波束赋形基础

    波束赋形（Beamforming）通过对多天线阵列各元件的信号施加不同的相位偏移和幅度权重，使信号在特定方向上相长干涉（形成主瓣），在其他方向上相消干涉（形成零陷）。

    对均匀线性阵列（ULA），目标方向 $\theta$ 的阵列响应向量为：

    $$\mathbf{a}(\theta) = \left[1,\ e^{j\frac{2\pi d}{\lambda}\sin\theta},\ e^{j\frac{4\pi d}{\lambda}\sin\theta},\ \ldots,\ e^{j\frac{2\pi(N-1)d}{\lambda}\sin\theta}\right]^T$$

    其中 $d$ 为阵元间距（通常取 $\lambda/2$），$\lambda$ 为波长，$N$ 为阵元数。波束赋形权重向量 $\mathbf{w} = \mathbf{a}(\theta)$ 时，主波束指向 $\theta$ 方向，3dB 波束宽度约为 $\frac{0.886\lambda}{Nd}$。

    5.2 三种波束赋形实现架构

    5.2.1 数字波束赋形（Digital Beamforming）

    原理：每根天线配备独立的射频链路（RF Chain）和数模转换器（DAC/ADC），预编码完全在基带数字域实现。

    优点：灵活性最高，可精确控制每根天线的幅度和相位，支持全维度 MU-MIMO。
    缺点：每根天线需一路 RF 链路，成本和功耗随天线数线性增长，不适合天线数极多的 mmWave 场景。
    典型应用：FR1（sub-6 GHz）Massive MIMO，4T4R～64T64R。

    5.2.2 模拟波束赋形（Analog Beamforming）

    原理：预编码在射频域通过移相器（Phase Shifter）实现，多根天线共享一路 RF Chain，仅能形成单一波束。

    优点：硬件成本低，适合天线数极多的 mmWave 阵列（如 256 或 512 元件）。
    缺点：同一时刻只能形成一个波束，不支持 MU-MIMO，波束切换有时延。
    典型应用：早期 FR2 设备（手机侧）。

    5.2.3 混合波束赋形（Hybrid Beamforming）

    原理：将数字和模拟结合——少量 RF Chain 在数字域独立控制，每路 RF Chain 连接一组天线子阵列（Sub-array）通过模拟移相器赋形。

    总预编码矩阵：$\mathbf{F} = \mathbf{F}{RF} \mathbf{F}{BB}$

    • $\mathbf{F}{RF} \in \mathbb{C}^{N_T \times N{RF}}$：模拟部分（仅相位可控，$|\mathbf{F}{RF}|{ij} = \text{const}$）
    • $\mathbf{F}{BB} \in \mathbb{C}^{N{RF} \times N_s}$：数字部分（幅度+相位均可控）

    典型参数（FR2 gNB 基站）：

    参数 典型值
    物理天线元件 $N_T$ 64 ～ 512
    RF Chain 数 $N_{RF}$ 4 ～ 32
    数字端口数 等于 $N_{RF}$
    可形成同时波束数 $N_{RF}$（上限）

    混合波束赋形是 5G NR FR2 基站的主流实现方案，在硬件复杂度与性能之间取得最优平衡。

    6. Massive MIMO 与混合波束赋形

    6.1 Massive MIMO 的定义

    Massive MIMO（大规模 MIMO）通常指基站侧配置数十至数百根天线，天线数远超同时服务的用户数。在 5G NR 中，Massive MIMO 没有严格的天线数量下限定义，但工业界通常以以下部署为代表：

    • FR1：32T32R 或 64T64R 有源天线阵列（AAS，Active Antenna System）
    • FR2：64 元件以上的相控阵（Phased Array）

    6.2 Full-Dimension MIMO（FD-MIMO）

    传统 MIMO 仅在水平维度（方位角 Azimuth）进行波束赋形，FD-MIMO 增加了垂直维度（俯仰角 Elevation）的控制能力，形成三维波束赋形（3D Beamforming）：

    3D 波束赋形使 gNB 能够区分同一水平方向但不同楼层的 UE（高楼场景），大幅提升用户隔离度。

    6.3 Massive MIMO 的关键性能收益

    根据运营商公开数据：

    • NTT DOCOMO 3.7 GHz：32T32R 面板，8 SSB 波束 + 32 CSI-RS 精细波束，单小区峰值 1.5 Gbps，覆盖 5.4 万基站。
    • Verizon 28 GHz mmWave：8 SSB 波束 + 64 CSI-RS 精细波束，小区边缘平均吞吐量 300 Mbps。

    7. CSI 反馈框架：码本与测量

    3GPP 在 TS 38.214 clause 5.2 中定义了完整的 CSI 反馈框架，包括码本（Codebook）设计和CSI 报告配置。

    7.1 CSI 反馈三元组

    UE 上报以下三个量（TS 38.214 clause 5.2.1）：

    反馈量 全称 含义
    CQI Channel Quality Indicator 推荐 MCS 索引（0～15），反映信道质量
    PMI Precoding Matrix Indicator 推荐预编码矩阵的码本索引
    RI Rank Indicator 推荐传输层数（1～8）

    CQI 到 MCS 的映射见 TS 38.214 Table 5.2.2.1-3，PMI 构成取决于码本类型。

    7.2 码本类型

    Type I 码本（单面板，TS 38.214 clause 5.2.2.2.1）

    Type I 码本采用双级预编码结构（Dual-Stage）：

    $$\mathbf{W} = \mathbf{W}_1 \mathbf{W}_2$$

    • $\mathbf{W}_1$：宽带（Wideband）预编码，反映信道主方向，由 $i_1$ 索引
    • $\mathbf{W}_2$：子带（Subband）预编码，细化频域差异，由 $i_2$ 索引

    Type I 码本分为单面板（Single-Panel）和多面板（Multi-Panel）两类。单面板支持天线配置 $N_1 \times N_2$（$N_1$ 为水平元件数，$N_2$ 为垂直元件数），最大 32 端口（$N_1 \times N_2 \times 2 \leq 32$）。

    适用场景：SU-MIMO，中等精度 CSI 要求，FR1 sub-6 GHz 主流部署。

    Type II 码本（TS 38.214 clause 5.2.2.2.3）

    Type II 码本设计用于精确 MU-MIMO 预编码，采用线性组合形式：

    $$\mathbf{W}1 = \sum{l=1}^{L} c_l \mathbf{b}_l$$

    其中 $\mathbf{b}_l$ 为从 2D 离散傅里叶变换（DFT）过采样码本中选出的 $L$（1～4）个正交波束向量，$c_l$ 为复数组合系数。

    Type II 码本开销显著高于 Type I（反馈比特数增加 3～5 倍），但提供更精确的空间信道描述，使 gNB 能更好地消除 MU-MIMO 用户间干扰。

    Enhanced Type II 码本（eType II，R16，TS 38.214 clause 5.2.2.2.5）

    eType II 在 R16 引入，针对宽带 Massive MIMO 场景进行频域压缩：

    • 引入频域基向量（Frequency Domain Basis），用少量 DFT 分量表示跨频带的信道变化
    • 显著减少 Type II 的反馈开销（约降低 50%），同时保持接近 Type II 的精度
    • 支持最多 32 端口，适合大带宽（100 MHz）场景

    7.3 CSI-RS 资源配置

    gNB 通过 CSI-RS（Channel State Information Reference Signal）信号供 UE 测量信道。TS 38.214 clause 5.1.6 定义了 CSI-RS 资源集配置：

    CSI-RS 端口数可配置为 1, 2, 4, 8, 12, 16, 24, 32 个（TS 38.211 Table 7.4.1.5.3-1），对应不同的天线阵列规模。

    7.4 CSI 报告触发类型

    类型 触发方式 承载信道 特点
    周期性（Periodic） 固定周期 PUCCH 低开销，适合慢速移动
    半持续（Semi-Persistent） 激活后周期 PUCCH / PUSCH 可暂停/重激活
    非周期性（Aperiodic） DCI 触发 PUSCH 按需精确测量，开销灵活

    8. 波束管理（Beam Management）

    波束管理（BM，Beam Management）是 5G NR 在连接态下持续维护最优波束对（Beam Pair Link，BPL）的机制，定义于 TR 38.802 clause 6.1.6 和 TS 38.213 clause 4。

    8.1 P1/P2/P3 下行波束管理框架

    3GPP 定义了三个相互配合的波束管理过程：

    P1：初始波束选择

    目标：从所有可能的波束方向中，选择初始最优发送-接收波束对。

    过程：

    1. gNB 在半帧（5 ms）内扫描发送 SSB 突发集（SSB Burst Set），每个 SSB 使用不同的 Tx 波束方向
    2. UE 在每个 SSB 机会上尝试不同的 Rx 波束（若 UE 支持模拟波束赋形）
    3. UE 测量每个 SSB 的 SS-RSRP（Synchronization Signal Reference Signal Received Power）
    4. UE 通过 RACH Msg1（选择对应 PRACH 资源）或 L1 信令上报最佳 SSB 索引
    5. gNB 据此确定初始服务波束

    SSB 波束数量（TS 38.213 clause 4.1）：

    频率范围 子载波间隔 最大 SSB 数 $L_{max}$
    FR1 ≤ 3 GHz 15 kHz 4
    FR1 3～6 GHz 30 kHz 8
    FR2（mmWave） 120 kHz 64
    FR2（mmWave） 240 kHz 64

    P2：gNB 侧发送波束精细化

    目标：在 P1 确定的粗略方向附近，用更窄的 CSI-RS 波束进一步精细化 gNB 的 Tx 波束。

    过程：

    1. gNB 在最佳 SSB 方向附近配置若干 CSI-RS 资源（波束比 SSB 更窄），设置 repetition = ON（波束扫描模式）
    2. UE 保持 P1 确定的最佳 Rx 波束固定不变
    3. UE 测量每个 CSI-RS 资源的 L1-RSRP（Layer 1 RSRP） 和 CRI（CSI-RS Resource Indicator）
    4. UE 通过 PUCCH 或 PUSCH 上报 CRI 和 L1-RSRP
    5. gNB 将 Tx 波束切换至最优 CSI-RS 对应方向

    实测收益：P2 精细化后，相比 P1 初始 SSB 波束，信道增益通常可提升 3～6 dB，对应约 2～4 倍的吞吐量提升（以小区边缘 UE 为例）。

    P3：UE 侧接收波束精细化

    目标：在 gNB Tx 波束固定的条件下，UE 自主搜索最优 Rx 波束（仅适用于支持 Rx 模拟波束赋形的 UE，如 FR2 设备）。

    过程：

    1. gNB 在 P2 确定的最优 Tx 方向发送 CSI-RS（repetition = ON，多个 CSI-RS 机会上保持相同 Tx 波束）
    2. UE 在不同 CSI-RS 机会上切换自身的 Rx 波束
    3. UE 内部选择最优 Rx 波束（无需上报，UE 自主决定，隐式操作）
    4. gNB Tx 波束保持不变，UE Rx 波束自动更新

    8.2 波束测量量

    测量量 定义 应用场景 规范
    SS-RSRP SSB 参考信号接收功率 P1 初始波束选择 TS 38.215 clause 5.1.1
    SS-RSRQ SSB 参考信号接收质量 补充 RSRP 判断 TS 38.215 clause 5.1.3
    L1-RSRP 第一层 RSRP（CSI-RS/SSB） P2/P3 精细波束选择 TS 38.215 clause 5.1.2
    L1-SINR 第一层信干噪比 R16+ 增强波束报告 TS 38.215 clause 5.1.5
    CRI CSI-RS 资源指示 标识最优 CSI-RS 波束 TS 38.214 clause 5.2.1

    9. 准同址（QCL）与 TCI 状态

    9.1 准同址（QCL）的定义

    准同址（QCL，Quasi-Co-Location）是 5G NR 中的关键概念，定义于 TS 38.214 clause 5.1.5：若信号 A 与信号 B 满足 QCL 关系，则 UE 可以从信号 A 的测量中推断信号 B 的某些信道特性，从而优化接收。

    3GPP 定义了四种 QCL 类型：

    QCL 类型 可推断的信道特性 典型用途
    Type A 多普勒频移、多普勒扩展、平均时延、时延扩展 定时和频率同步
    Type B 多普勒频移、多普勒扩展 频率同步
    Type C 多普勒频移、平均时延 时延辅助定时
    Type D 空间接收参数（Spatial Rx Parameter） 波束方向推断（FR2 核心机制）

    QCL Type D 是波束管理的核心：若 CSI-RS 与 SSB 之间存在 Type D 的 QCL 关系，则 UE 可用接收 SSB 的波束来接收该 CSI-RS，无需重新搜索最优 Rx 波束。

    9.2 TCI 状态（Transmission Configuration Indication State）

    TCI 状态（TS 38.214 clause 5.1.5）是 gNB 通知 UE 使用哪个参考信号作为 QCL 基准的机制：

    TCI 状态激活流程：

    1. gNB 通过 RRC 信令配置最多 128 个 TCI 状态（TS 38.331 TCI-State IE）
    2. gNB 通过 MAC CE 激活其中 8 个 TCI 状态为候选集
    3. gNB 通过 DCI field（1 bit 或 3 bits）在调度时指示具体使用哪个 TCI 状态
    4. UE 根据 TCI 指示，使用对应参考信号的 Rx 波束接收 PDCCH 或 PDSCH

    激活时延（TS 38.214 clause 5.1.5）：

    • MAC CE 激活 TCI 状态后，生效时延为：3 ms + 处理时延

    9.3 默认波束行为

    在未收到明确 TCI 指示时，UE 遵循默认 QCL 规则（TS 38.214 clause 5.1.5）：对于 PDSCH，在 timeDurationForQCL 时间段内，UE 使用与调度该 PDSCH 的 PDCCH 相同的 TCI 状态进行接收。

    10. 波束失败检测与恢复（BFR）

    10.1 波束失败场景

    在 FR2 mmWave 场景中，波束阻塞（Beam Blockage）是主要挑战：人体、车辆、建筑物等遮挡可在毫秒级时间内使当前服务波束的信号质量骤降，触发波束失败（Beam Failure）。

    10.2 波束失败检测（TS 38.321 clause 5.17）

    gNB 配置 UE 以特定参考信号（SSB 或 CSI-RS）进行波束失败检测，UE 对这些信号计算假想 BLER（Block Error Rate）。当以下条件满足时，PHY 层向 MAC 层上报一次波束失败实例：

    $$\text{假想 BLER}(t) > q_{out}^{LR} \approx 0.1$$

    当在 beamFailureDetectionTimer 时间内，波束失败实例累计达到 beamFailureInstanceMaxCount（可配置，典型值 1～8），MAC 层宣告波束失败。

    10.3 候选波束识别

    波束失败宣告后，UE 立即在配置的候选波束参考信号集合（Candidate Beam RS List）中搜索新的可用波束：

    若无任何候选波束满足阈值，UE 可选择 L1-RSRP 最高的 SSB（无门限要求）作为候选。

    10.4 BFR 信令流程

    BFR 关键计时器（TS 38.321）：

    • beamFailureRecoveryTimer：BFR 请求发送后等待 gNB 响应的超时时间
    • 超时后 UE 可重传 BFR 请求，最多 maxBFR-PUSCH-Resources 次

    10.5 主小区（PCell）与辅小区（SCell）的 BFR 差异

    场景 接入方式 特点
    PCell 波束失败 RACH 接入 通用性强，支持竞争和免竞争
    SCell 波束失败（R16） MAC CE + PUSCH 更快恢复，无需完整 RACH 流程

    11. 上行波束管理：SRS 与 U1/U2/U3

    11.1 波束互易性（Beam Correspondence）

    在 TDD 系统中，若满足波束互易性（Beam Correspondence），则 gNB 可用下行最优波束方向推断上行最优波束方向，省去上行波束搜索开销。NR 规范允许但不强制要求 UE 支持波束互易性（TS 38.101-1 clause 6.4A）。

    当 UE 不支持波束互易性（或 FDD 系统）时，需要独立的上行波束管理流程。

    11.2 SRS 与上行波束管理

    SRS（Sounding Reference Signal）是上行波束管理的核心参考信号，定义于 TS 38.214 clause 6.1.1。

    SRS 资源集可配置为以下用途（usage 字段，TS 38.331 SRS-ResourceSet IE）：

    • beamManagement：波束管理，gNB 扫描 UE 发送的不同 Tx 波束方向
    • codebook：码本上行预编码
    • nonCodebook：非码本上行预编码
    • antennaSwitching：天线切换增益

    11.3 U1/U2/U3 上行波束管理流程

    类比下行 P1/P2/P3，上行波束管理分为三个过程：

    过程 目标 发送端 接收端
    U1 UE Tx 波束初始选择 UE 扫描 SRS Tx 波束 gNB 扫描 Rx 波束
    U2 gNB Rx 波束精细化 UE 固定 Tx 波束 gNB 扫描多 Rx 波束
    U3 UE Tx 波束精细化 UE 扫描 Tx 波束 gNB 固定 Rx 波束

    实践中，若下行 P1～P3 完成后存在波束互易性，则 U1～U3 可省略或简化，由 gNB 基于下行测量结果直接配置上行波束。

    12. FR1 vs FR2 多天线部署差异

    12.1 物理特性差异

    特性 FR1（410 MHz～7.125 GHz） FR2（24.25 GHz～52.6 GHz）
    路径损耗 相对低（衍射能力强） 高（28 GHz 比 3.5 GHz 约高 18 dB）
    穿透损耗 低～中（玻璃 3 dB，混凝土 20 dB） 极高（人体 30 dB+，墙体 40 dB+）
    信道散射 富散射，多径丰富 稀疏散射，路径数少
    最大 SSB 波束数 4 ～ 8 64
    主要波束赋形方式 数字（FD-MIMO） 混合（Hybrid BF）

    12.2 FR1 Massive MIMO 部署

    • 天线面板：有源天线阵列（AAS），典型 32T32R 或 64T64R
    • 波束赋形维度：方位角 + 俯仰角（FD-MIMO / 3D BF）
    • SSB 波束：4 或 8 个，覆盖 120° 扇区
    • CSI-RS 精细波束：每 SSB 方向内 4～16 个 CSI-RS 波束
    • MU-MIMO 能力：最多 8 个 UE 同时配对（8 个空间流）
    • 典型 BS 配置：$N_1 = 8$，$N_2 = 4$（水平 8 × 垂直 4），双极化，32 数字端口

    12.3 FR2 mmWave 部署

    • 天线面板：相控阵（Phased Array），64 ～ 512 物理元件
    • 波束赋形方式：混合波束赋形（4～8 路 RF Chain + 模拟移相器）
    • SSB 波束：最多 64 个，覆盖 120° 扇区（每波束约 2° 宽）
    • CSI-RS 精细波束：每 SSB 方向内 8 个 CSI-RS 波束（更窄）
    • MU-MIMO 限制：RF Chain 数量限制并发用户数，通常 2～4 个
    • 波束更新周期：更频繁（毫米波阻塞随机性高），typically ~20 ms
    • UE 侧：手机集成多面板（如前后各一块）配合天线切换

    13. Release 演进：R15 → R18 增强点

    R15（基础版本）

    • SU-MIMO / MU-MIMO 基础框架（最多 8 层 DL / 4 层 UL）
    • P1 / P2 / P3 下行波束管理
    • Type I 单面板和多面板码本
    • Type II 码本（高精度 MU-MIMO 反馈）
    • BFR（波束失败恢复）基础流程（PCell）
    • QCL 四种类型（A/B/C/D）+ TCI 状态机制

    R16（增强版本）

    • eType II 码本（Enhanced Type II）：频域压缩，减少 50% 反馈开销
    • L1-SINR 报告：新增 SINR 作为波束测量量，提升 MU-MIMO 配对精度
    • SCell BFR：辅小区（SCell）波束失败快速恢复，无需完整 RACH
    • 多 TRP 传输：多个传输接收点协作波束管理（multi-TRP）
    • PDCCH 波束管理：针对 CORESET 的独立 TCI 配置

    R17（RedCap 与增强）

    • 统一 TCI 框架（Unified TCI）：下行和上行 TCI 统一配置，简化信令
    • 多面板 UE 支持：UE 侧多面板间波束切换增强
    • NTN（非地面网络）波束管理：适配卫星通信的大延迟特性

    R18（5G-A / Advanced）

    • AI/ML 辅助波束管理：引入机器学习用于波束预测，减少 BFR 中断时延
    • eType II 进一步增强：支持更高压缩比，适配 6 GHz 频段
    • 更大天线端口：支持超过 32 个数字端口的 Massive MIMO 配置
