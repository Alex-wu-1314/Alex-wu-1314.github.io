    1. 为什么需要多套标识体系？

    在蜂窝网络中，”我是谁”这个问题并不简单。同一个用户在不同场景、不同协议层次下需要向网络出示不同的”证件”。设计多套标识符的主要动机来自三个维度：

    维度 问题 解决方案
    隐私保护 若始终用固定身份标识，攻击者可追踪用户位置 引入临时标识（GUTI）和加密标识（SUCI）
    效率优化 核心网标识（如 SUPI）过长，不适合无线资源调度 引入短小的无线侧临时标识（RNTI）
    管理分层 订阅者身份与设备身份需分开管理（SIM 可换卡） SUPI/IMSI 代表订阅者，IMEI/PEI 代表设备硬件

    理解这一点，就理解了 5G NR 标识体系的设计逻辑。

    3. IMSI：永久订阅者身份

    3.1 定义与来源

    IMSI（International Mobile Subscriber Identity，国际移动用户识别码）是 3GPP 网络中标识订阅者的基础标识符，源自 2G/GSM 时代，在 4G LTE 和 5G 中仍然沿用（5G 中被 SUPI 封装）。IMSI 存储在 USIM（Universal Subscriber Identity Module）中，同时也存储在运营商核心网的 UDM/UDR（User Data Management / User Data Repository）中。

    3.2 结构与格式

    IMSI 是一串最长 15 位十进制数字，由 ITU-T E.212 规定：

    各字段说明：

    字段 全称 长度 说明
    MCC Mobile Country Code 3 位十进制 国家码，如中国 460、美国 310
    MNC Mobile Network Code 2~3 位十进制 运营商码，如中国移动 00、中国联通 01
    MSIN Mobile Subscriber Identification Number 9~10 位十进制 在该运营商网络内唯一标识某一用户

    示例：460001234567890

    • 460：中国
    • 00：中国移动
    • 1234567890：该用户的 MSIN

    3.3 安全隐患：IMSI Catcher

    IMSI 是永久标识符，若在无线接口上明文传输，攻击者可通过伪基站（IMSI Catcher / Stingray）捕获用户 IMSI，进而跟踪用户位置。这一问题贯穿 2G/3G/4G 全代，是 5G 引入 SUCI 机制的直接动因。

    4. SUPI：5G 订阅永久标识符

    4.1 定义

    SUPI（Subscription Permanent Identifier，订阅永久标识符）是 5G 系统中标识订阅者的全局唯一永久标识符，定义于 3GPP TS 23.501 §5.9.2，结构细节见 TS 23.003。

    SUPI 只在 3GPP 系统内部使用，永远不应明文传输到无线接口上，其隐私保护由 SUCI 机制负责。SUPI 值同时预配置于 USIM 和运营商的 UDM/UDR 中。

    4.2 两种形态

    SUPI 支持两种格式（TS 23.003）：

    ① 基于 IMSI 的 SUPI（最常见，适用于 3GPP RAT）

    这种形式确保了与 4G EPC 的互操作性：当 UE 需要从 5G 回落到 4G 时，可直接将 SUPI 中的 IMSI 呈现给 EPC。

    ② 基于 NAI 的 SUPI（适用于非 3GPP RAT，如 Wi-Fi 接入）

    NAI（Network Access Identifier）格式遵循 RFC 7542，用于通过非 3GPP 接入（如可信 Wi-Fi、不可信 Wi-Fi）接入 5GC 的场景。

    4.3 与 IMSI 的关系

    可以将 SUPI 理解为 5G 系统对 IMSI 概念的”升级封装”：

    • 当接入 3GPP 无线接入（NR）时，SUPI 的值与 IMSI 相同
    • 当接入非 3GPP 时，SUPI 可为 NAI 格式
    • 对于需要与 EPC 互通的 5G UE，SUPI 必须基于 IMSI（TS 23.501 §5.9.2）

    5. SUCI：订阅隐藏标识符

    这是 5G 在安全设计上相对 4G 的主要改进之一。

    5.1 设计背景与目标

    3GPP TS 33.501 明确规定：5G 系统不允许在无线接口上明文传输 SUPI。当 UE 首次注册、或网络无法通过 GUTI 识别 UE 身份时，UE 必须提供其加密后的身份，即 SUCI。

    SUCI（Subscription Concealed Identifier） 是一种保护隐私的标识符，它包含经过加密隐藏的 SUPI，使空口监听者无法从中还原出真实订阅者身份。

    5.2 加密机制：ECIES

    SUCI 的加密基于 ECIES（Elliptic Curve Integrated Encryption Scheme，椭圆曲线集成加密方案），属于非对称加密（公钥密码学）。TS 33.501 Annex C 规定了两种曲线 Profile：

    Profile 椭圆曲线 特点
    Profile A Curve25519 高效，适合资源受限设备
    Profile B NIST P-256（secp256r1） 与 NIST SP 800-56A 兼容，更广泛兼容性

    5.3 SUCI 的组成字段（TS 23.003）

    • Routing Indicator：用于在归属网络中路由到正确的 UDM 实例（TS 23.003 §2.2B）
    • Protection Scheme = Null：不加密，MSIN 明文可见（不推荐，仅在特定场景或测试中使用）
    • Scheme Output：仅 MSIN 部分被加密，MCC/MNC 等路由信息仍为明文，确保网络能够路由请求到正确的归属网络

    5.4 SUCI 的一次性特性

    每次生成 SUCI 时，UE 都会使用新鲜的临时密钥对，因此每次 SUCI 值都不同，即使 SUPI 相同也无法关联两次不同的注册请求。这从根本上消除了 IMSI Catcher 的跟踪能力。

    6. GUTI / 5G-GUTI：全球唯一临时标识符

    6.1 设计目的

    5G-GUTI（5G Globally Unique Temporary Identifier）是 AMF 分配给 UE 的临时标识符，用于在注册成功后代替 SUPI/SUCI 进行后续信令交互，从而：

    1. 避免每次信令都暴露 SUPI（或发送计算代价较高的 SUCI）
    2. 让网络能够快速路由信令到正确的 AMF

    定义于 TS 23.501 §5.9.4 和 TS 23.003 §2.10B。

    6.2 5G-GUTI 结构（完整 80 bits）

    各字段详解：

    字段 长度 说明
    MCC 12 bit（3 位十进制） 国家码，标识所属 PLMN
    MNC 8 或 12 bit（2~3 位十进制） 运营商码
    AMF Region ID 8 bit 标识 AMF 所在区域，支持运营商在不同 Region 中复用相同 Set ID
    AMF Set ID 10 bit 在 AMF Region 内唯一标识一个 AMF Set
    AMF Pointer 6 bit 标识 AMF Set 内的一个或多个 AMF 实例
    5G-TMSI 32 bit 在该 AMF（或共用 GUAMI 的 AMF 组）内唯一标识 UE

    GUAMI（Globally Unique AMF Identifier） = MCC + MNC + AMF Region ID + AMF Set ID + AMF Pointer，共 48 bit，唯一标识一个 AMF 实例或 AMF 集合。

    6.3 5G-S-TMSI：寻呼用简短形式

    在寻呼（Paging）和服务请求（Service Request）等无线侧流程中，传输完整 5G-GUTI（80 bit）会增加空口开销。为此，TS 23.501 §5.9.4 定义了简短形式：

    NG-RAN 在寻呼时使用 5G-S-TMSI 的低 10 位（Least Significant Bits of 5G-TMSI）来确定 UE 在哪个寻呼时机（Paging Occasion）被呼叫（TS 38.304），因此 AMF 在分配 5G-TMSI 时需确保低 10 位均匀分布。

    6.4 5G-GUTI 的分配时机

    根据 TS 23.501 和 TS 33.501 §6.12.3，AMF 在以下时机分配新的 5G-GUTI：

    • UE 发送初始注册请求（Initial Registration）或移动性注册更新（Mobility Registration Update）后，AMF 在 Registration Accept 中必须（SHALL）分配新的 5G-GUTI
    • UE 发送周期性注册更新（Periodic Registration Update）后，AMF应（SHOULD）分配新的 5G-GUTI
    • AMF 可在任意时刻主动重新分配 5G-GUTI（如安全考虑或负载均衡）
    • 当 UE 处于 CM-IDLE 状态时，AMF 可推迟到下次 NAS 事务时再分配

    7. IMEI / IMEISV / PEI：设备永久标识符

    7.1 区别于订阅者标识的设备标识

    IMSI/SUPI 标识的是”哪个用户的订阅”（SIM 卡/USIM），而 IMEI 标识的是”哪台物理设备”（手机硬件）。用户可以把 SIM 卡从 A 手机拔出插入 B 手机，这时 IMSI 不变但 IMEI 变化。

    7.2 IMEI 结构（15 位十进制）

    定义于 3GPP TS 23.003 §6：

    字段 长度 说明
    TAC（Type Allocation Code） 8 位十进制 由 GSMA 统一分配给设备厂商，标识设备型号和来源。TAC 可用于设备类型识别
    SNR（Serial Number） 6 位十进制 由厂商在同一 TAC 下按顺序分配，唯一标识每台设备
    CD（Check Digit） 1 位十进制 使用 Luhn 算法计算的校验位，用于检测手动输入错误。传输时通常设为 0（Spare）

    校验位：采用 Luhn（模 10）算法，防止手工抄写错误（如客户到运营商报告手机丢失时使用）。

    示例：35 123456 789012 3（格式仅为可读性，实际无分隔符）

    7.3 IMEISV 结构（16 位十进制）

    IMEISV（IMEI Software Version Number）在 IMEI 基础上增加了软件版本字段：

    • SVN（Software Version Number）：2 位十进制，由设备厂商分配，标识当前固件/软件版本。SVN 值 99 预留作将来使用
    • IMEISV 没有 CD（校验位），用 SVN 替换了 CD 的位置

    IMEISV 主要用于网络侧识别设备软件版本，例如在切换（Handover）场景中网络需要知道 UE 的软件能力。

    7.4 PEI：5G 设备永久标识符

    在 5G 系统中，TS 23.501 §5.9.3 引入 PEI（Permanent Equipment Identifier），作为设备标识的统一抽象：

    • 对于支持至少一种 3GPP 接入技术的 UE：PEI 必须采用 IMEI 或 IMEISV 格式
    • 对于仅使用非 3GPP 接入（W-5GAN）的 UE：PEI 可使用 EUI-64（IEEE 扩展唯一标识符）等其他格式
    • 当前 Release 15/16 实现中，PEI 主要以 IMEI 格式出现

    PEI 在以下场景使用：

    • 设备检查（Equipment Identity Check）：AMF 向 UDM 查询 UE 的 PEI，或向 EIR（Equipment Identity Register）核查设备是否在白名单/黑名单中
    • 注册流程：AMF 在必要时通过 Identity Request 向 UE 请求 PEI

    7.5 EIR：设备黑白名单管理

    EIR（Equipment Identity Register）是核心网中管理 IMEI 黑/白/灰名单的功能实体，在 5GC 中由 5G-EIR 承担。运营商可以通过 EIR 阻止被盗设备（黑名单 IMEI）接入网络。

    8. RNTI：无线网络临时标识符

    RNTI（Radio Network Temporary Identifier，无线网络临时标识符）是纯粹的无线接入层（RAN 层）标识符，与核心网无关，用于在 PDCCH（物理下行控制信道）上区分不同用途的调度信息。

    定义于 3GPP TS 38.321（MAC 协议）和 TS 38.212（信道编码）。

    8.1 RNTI 的基本原理

    RNTI 用于对 PDCCH 上 DCI（Downlink Control Information）的 CRC 比特进行加扰（Scrambling）。UE 在盲检测 PDCCH 时，用自身持有的各类 RNTI 去解扰 CRC，若 CRC 校验通过则判断该 DCI 是发给自己的（或自己应关注的广播/组播信息）。

    除 I-RNTI（40 bit 或 24 bit）外，所有 RNTI 均为 16 bit。

    8.2 RNTI 类型详解

    以下是 TS 38.321 Table 7.1-2 中定义的 5G NR RNTI 全集：

    （1）调度与数据传输类 RNTI

    RNTI 全称 分配者 作用 取值范围
    C-RNTI Cell RNTI gNB 标识 RRC_CONNECTED 态的某个 UE，用于专用数据/控制调度（PDSCH/PUSCH），每个 UE 在当前服务小区内唯一 0x0001~0xFFCF
    CS-RNTI Configured Scheduling RNTI gNB 半静态调度（SPS，Semi-Persistent Scheduling）使用，激活或去激活 SPS 下行传输 0x0001~0xFFCF
    MCS-C-RNTI MCS-Cell RNTI gNB 用于使用特殊 MCS 表格的动态调度场景（R16 引入） 0x0001~0xFFCF

    （2）随机接入类 RNTI

    RNTI 全称 分配者 作用 取值
    RA-RNTI Random Access RNTI 由 PRACH 时频资源决定，UE 自行计算 标识某次随机接入尝试，gNB 在 RAR（Msg2）中使用 RA-RNTI 作为地址，UE 据此识别属于自己的 RAR 由公式计算：RA-RNTI = 1 + s_id + 14*t_id + 14*80*f_id + 14*80*8*ul_carrier_id
    TC-RNTI Temporary C-RNTI gNB（包含在 RAR 中） 随机接入过程中的临时标识，RAR 中携带，用于 Msg3 的 CRC 加扰（竞争解决前），竞争解决成功后升级为 C-RNTI 0x0001~0xFFCF

    （3）广播与寻呼类 RNTI

    RNTI 全称 固定值 作用
    SI-RNTI System Information RNTI 0xFFFF（65535） 用于广播系统信息（SIB）调度，所有 UE 共用，无需单独分配
    P-RNTI Paging RNTI 0xFFFE（65534） 用于寻呼消息调度或 Short Message（通知 SIB 更新/ETWS/CMAS 告警）传输

    （4）功率控制类 RNTI

    RNTI 作用
    TPC-PUCCH-RNTI gNB 向一组 UE 发送 PUCCH 功率控制命令
    TPC-PUSCH-RNTI gNB 向一组 UE 发送 PUSCH 功率控制命令
    TPC-SRS-RNTI gNB 向一组 UE 发送 SRS 功率控制命令

    （5）调度控制类 RNTI（NR 新增）

    RNTI 全称 作用
    SFI-RNTI Slot Format Indicator RNTI TDD 动态时隙格式指示，通知 UE 当前 slot 的上/下行/灵活符号配置
    INT-RNTI Interruption RNTI 下行抢占指示（Preemption Indication），通知 UE 其接收中被高优先级流量中断的资源范围
    SP-CSI-RNTI Semi-Persistent CSI RNTI 激活/去激活半静态 CSI 上报配置

    （6）非激活态标识 RNTI（NR 特有）

    RNTI 全称 长度 作用
    I-RNTI Inactive RNTI 40 bit（Full）/ 24 bit（Short） 标识 RRC_INACTIVE 状态的 UE，由锚点 gNB（Anchor gNB，即保存 UE 上下文的 gNB）分配。当 UE 从 INACTIVE 恢复时，gNB 可通过 I-RNTI 从锚点 gNB 取回 UE 上下文，避免重新建立完整 RRC

    I-RNTI 的特殊性：这是 5G NR 相对 4G LTE 新增的状态（RRC_INACTIVE），为了在保持连接上下文的同时降低信令和功耗开销。I-RNTI 同时标识 UE 身份和锚点 gNB，使 UE 上下文可在 gNB 间迁移。

    9. 其他补充标识符

    9.1 GPSI：通用公共订阅标识符

    GPSI（Generic Public Subscription Identifier）是用于在 3GPP 系统外部标识订阅者的标识符（TS 23.501 §5.9.8）：

    • MSISDN 形式：即电话号码（E.164 格式），如 +8613800138000，用于语音/SMS 寻址
    • 外部 NAI 形式：用于数据网络（如 IMS、MEC 应用）识别用户

    GPSI 对外暴露，但不等于 SUPI。两者的映射关系存储在 UDM 中。

    9.2 TMSI / 5G-TMSI

    5G-TMSI 是 5G-GUTI 中的 UE 本地标识部分（32 bit），在 AMF 内唯一标识某个 UE。它是 4G M-TMSI 的 5G 对应物。

    9.3 RAN-UE-NGAP-ID / AMF-UE-NGAP-ID

    在 NG 接口（gNB 与 AMF 之间的 N2 接口，协议为 NGAP）上，UE 由一对 ID 标识：

    • RAN-UE-NGAP-ID：由 gNB 分配，在该 gNB 范围内唯一标识某个 UE 的 NG 连接
    • AMF-UE-NGAP-ID：由 AMF 分配，在该 AMF 范围内唯一标识某个 UE 的 NG 连接

    两者结合，唯一确定 NG 接口上的一条 UE 关联（UE-Associated Logical NG-Connection）。这两个标识符属于接口层面，不直接暴露给 UE 或外部网络。

    11. 标识符安全性对比：从 2G 到 5G 的演进

    问题 2G/3G 4G LTE 5G NR
    IMSI 保护 无，IMSI 明文传输 有临时标识（GUTI），但首次或 GUTI 失效时仍需明文传 IMSI SUCI 加密，永不明文传 SUPI/IMSI
    IMSI Catcher 防护 无 弱（可被强制泄露 IMSI） 强（ECIES 非对称加密，每次 SUCI 不同）
    临时标识 TMSI（P-TMSI） GUTI（含 MMEGI+MMEC+M-TMSI） 5G-GUTI（含 GUAMI+5G-TMSI）
    设备标识保护 IMEI 明文 IMEI 明文 PEI，传输受 NAS 安全保护
    抗量子能力 无 无 ECIES 目前非量子安全（业界在研究 PQC 替代方案）

    12. 总结

    5G NR 的 UE 标识体系采用分层设计，主要思想是：

    1. 永久身份不上空口：SUPI（含 IMSI）只在 3GPP 系统内部流转，空口用 SUCI（加密）替代
    2. 临时身份降低追踪风险：5G-GUTI 频繁更新，缩短可追踪窗口
    3. 订阅与设备分离管理：SUPI/GUTI 跟着 SIM 走，IMEI/PEI 跟着设备走，EIR 管设备黑名单
    4. 无线侧专用轻量标识：RNTI 体系在 MAC 层高效完成调度寻址，与核心网标识完全解耦
    标识符 维度 作用层 可变性 定义规范
    SUPI/IMSI 订阅者 核心网（永不上空口） 永久 TS 23.003/23.501
    SUCI 订阅者 空口（加密） 每次不同 TS 33.501
    5G-GUTI 订阅者 NAS / 核心网 频繁更新 TS 23.003/23.501
    5G-S-TMSI 订阅者 RAN（寻呼） 跟随 GUTI TS 23.003
    IMEI/IMEISV/PEI 设备 核心网 永久 TS 23.003
    C-RNTI 订阅者 RAN（MAC 层） 每次接入变化 TS 38.321
    I-RNTI 订阅者 RAN（INACTIVE） 每次 INACTIVE 变化 TS 38.321
    RA-RNTI 随机接入资源 RAN（MAC 层） 每次接入计算 TS 38.321
